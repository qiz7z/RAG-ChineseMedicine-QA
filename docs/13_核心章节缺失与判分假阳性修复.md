## 缺陷 14：核心章节被 -饮片 子条目吞掉（85% 主条目受影响）

### 发现路径

问「生成的效果咋样」→ 拉分题型数据 → **否定性问题覆盖率只有 20%**，
且一批基础题（麻黄注意事项/天麻性味归经/茯苓来源…）的回答全是"资料中未收录"。
追查这些"未收录"是不是真的没资料：

```
step1  麻黄/天麻 的切片里只有 鉴别/含量测定/性状… 没有【性味与归经】【功能与主治】
step2  但正文里"发汗散寒""息风止痉"都能搜到 → 内容在，章节归属错了
step3  全量统计（⚠️ 这一版统计是**误报**，见下方"修正"）：2,183 个主条目里 1,855 个缺核心章节
       ——因为它拿"药材才有的章节"去量了 1,565 个成方制剂（中成药根本没有【性味与归经】）
step4  对照 麻黄（无饮片子条目，章节齐全）vs 天麻/人参/黄芪（有饮片，主条目全缺）
       → 根因：解析器按"最后一个条目边界"归属，
         药典排版里出现在【饮片】块**之后**的
         【性味与归经】【功能与主治】【用法与用量】【注意】【贮藏】
         全被挂到了 -饮片 子条目上
```

### 后果链

```
主条目缺核心章节
→ 查询「天麻的性味归经」解析出章节[性味与归经]
→ 语料里没有天麻主条目的承载切片（内容在 天麻-饮片/完整条目 里，
   但该切片不含"性味与归经"的独立段落标记结构，向量/BM25 都吃不到药名锚点）
→ 检索退化成返回 药品概要/含量测定
→ 生成只好答"资料未收录"（诚实，但答非所问）
→ 否定性问题覆盖率 20%、一批基础题 0 分
```

### ⚠️ 修正：真实缺口是 83 个药材，不是 85% 的主条目

复核分类后（按 `category_hint` 分组）：

| 类别 | 条目数 | 有【性味与归经】 |
|------|--------|-----------------|
| 药材和饮片 | 810 | **703（87%）** |
| 成方制剂和单味制剂 | 1,565 | **2（0%）** ← 中成药本来就没有这一章 |
| 植物油脂和提取物 | 46 | 0 |

所以正确口径是：**药材主条目 603 个里 83 个缺【性味与归经】（14%）、67 个缺【功能与主治】**，
其中 57 个两者都缺。**"85%" 是拿药材的章节标准去量成方制剂造成的误报**——
这个教训与 docs/11 的"口径不同结论不同"同源：**统计缺陷前必须先按类别分层**。

（缺陷 14 的回填机制本身是对的、也确实修好了天麻/人参/黄芪这类
「饮片侧有内容」的条目；错的只是我第一版统计的分母。）

### 修法（两处，都是小改动）

1. **`parser.py`：`_inherit_sections_from_yinpian`**——parse 末尾把 `-饮片` 子条目
   独有的核心章节回填给主条目。规则：
   - 只回填主条目**完全缺失**的章节，不覆盖已有；
   - ⚠️ **不能用长度阈值挡占位文本**：药典真实的性味与归经常只有
     「甘，平。归肝经。」8 个字，第一版 `len>=15` 的守卫把它误杀了
     （实测 5 个章节只回填出 1 个）。正确做法：去标点后 ≥3 字
     且**不是**「同药材」占位（占位文本拷了无信息量，真文本此时已无从恢复）；
   - 浅拷贝 Section，两条目各自持有。
2. **`chunker.py`：合并临床切片正文头部补药品名**。合并前的各章节正文里
   **没有药名**（「【性味与归经】甘，平。归肝经。」），
   BM25 的药名 token 得不到命中、向量缺锚点——实测会导致切片进不了候选池，
   章节提升再强也救不回没被召回的候选。

## 缺陷 16：Word 文本框内容未读取（已修）

### 根因

上面 83 个缺【性味与归经】的药材里，真正的原因是**内容存在 `w:txbxContent` 文本框里**：

```
文档里有 1,020 个文本框，共 20,517 字
框内承载：86 处【性味与归经】/ 90 处【功能与主治】/ 100 处【处方】/ 48 处【用法与用量】
parser.py 完全不处理 txbxContent（python-docx 的段落流也读不到）
```

决定性探针：大黄的「泻下攻积，清热泻火」在**整个语料 0 次命中**，却在 docx 文本框里躺着。

### 两类噪声（都必须处理）

| 噪声 | 实例 | 处理 |
|------|------|------|
| **裁切重复** | `辛，温;有小毒。归肝、脾、胃经。辛，温;有小毒。归肝、脾、胃` | 找**最短重复单元**（允许末段被裁切），压回一行 |
| **OCR 打碎的标记** | `1功能与主治】11功能与主治】功能与主治】`、`t性味与归经】tt性味与归经】性味与归【` | 若「章节名覆盖 ≥50% 且去掉所有章节名/子串后只剩噪声」→ 还原成 `【章节】` |

两个关键实现细节（都踩过）：

1. **重复单元的搜索上界要取 `n-3` 而不是 `n//2`**——"整份 + 裁切尾巴"是最常见形态，
   用 `n//2` 时找不到单元，实测 8 个样例里 6 个没压平；
2. **内容行不能被去空格**——第一版整行去掉空白，把拉丁学名
   `Rheum palmatum L.` 压成了 `RheumpalmatumL.`。
   正确做法：**按去空格版本检测重复，按原文截取**。

### 修法

`linearize_textboxes()`：把文本框内的段落**按锚点位置搬回正文流**，
后续解析逻辑（段落流 + 【章节】状态机）零改动。

### ⚠️ 插入段落会撞坏"药名-拼音"前瞻（必须同时修）

第一次跑完发现 **茜草整条消失**——内容跑到了 `荆芥穗炭` 名下。
根因：解析器判断"这是药名"依赖「本段是药名 **且下一段是拼音**」的前瞻
（`_next_is_pinyin`），而我插入的段落正好落在药名段与拼音段之间，把前瞻挡掉了
→ 该药名不再被认作条目边界 → 整条并进上一个药。

修法：`linearize_textboxes` 返回**插入的元素列表**，解析器记住它们的 id，
让**前瞻与边界判定都跳过**这些合成段落（它们只承载内容）。
修后条目数从被扰动的 2,432 回到 2,421 ✓。

> 这条教训很典型：**在文档流里"插入"内容，等于改动了所有依赖相邻关系的启发式**。
> 插入之后必须复查那些"看邻居"的判定（边界、软换行、拼音前瞻）。

### 缺陷 17：正文里的章节标记也被 OCR 打碎（已修）

#### ⚠️ 先纠正一次误判

我最初把剩余 54 个缺章节的药材归因为"版面位移"（内容块与表头块在 XML 里不相邻）。
只对了一半——**主因是章节标记本身被 OCR 打碎**：

```
正文段落里有 1,297 个「被打碎的章节标记」：
    t鉴别】（1）叶表面观…        （328 处，'t' 是【的误认）
    ［含量测定】总糖取本品粗粉…    （109 处）
    t检查】 水分 不得过13.0%…     （77 处）
    1功能与主治】                （74 处，标记独占一段、内容在下一段）
    t处方】 珊瑚75g珍珠15g…       （73 处）
    [:规格】 每粒装0.425g        （46 处）
        …（共 12 类）
```

解析器的章节正则要求段落**以 `【` 或 `〔` 开头**，这些段落因此**根本不被识别为章节**：

- 内容被**并进上一章节**（于是「鉴别」的正文跑到「性状」里）；
- 若正好在条目开头，则**整段丢失**。

这才是 54 个药材缺【性味与归经】的主因——其中 14 个直接写着 `t性味与归经】`。
实证：山麦冬的 `1性味与归经】甘、微苦，微寒。归心、肺、胃经。` 就在正文里，
只因前缀是 `1` 而被当成普通内容。

#### 修法

`normalize_ocr_section_markers()`：段落文本若匹配
`^[^【〔】〕]{0,4}[【〔\[]?(章节名)[】〕\]]`，就把首行改写成 `【章节名】rest`。

⚠️ **只取段落自己的 `w:t`（直接子 run 下的），不能用 `.//w:t`**——
锚点段落里可能嵌着文本框，用后者会把文本框内容一并清空（与缺陷 16 的坑同源）。

| 药材主条目有性味（含「性味」变体） | 550 / 604（91%） | **565 / 604（94%）** |

（`大蓟炭-饮片`↔大腹皮、`稻芽-饮片`↔僵蚕）。
修它需要按版面坐标重排内容，属缺陷 11/12 同族最难一类，暂缓。

## 缺陷 18：判分链路上的两处"指标说谎"（已修）

### 18a：`~` 被当 Markdown 删除线 → 剂量被粘成一个数

**复现**（模型回答原文，用户看到的是对的）：

```
**说明：**
- 常规剂量为每次6~12克          ← ASCII 波浪号，药典领域的**剂量区间分隔符**
```

`split_claims()` 里有 `_MD_INLINE_RE = re.compile(r"[*`_~]")`（去行内 Markdown 装饰），
它把 `~` 当**删除线标记**删掉：

```
论断（判官所见）= '常规剂量为每次612克'
判官判定        = contradicted ——「原文为6〜12g，非612克，数值不符」
```

判官没有错，**是喂给它的论断被我们自己的清洗规则粘错了**。药典里 `6〜12g` 是"六到十二克"，
`〜`/`～`/`~` 三种写法在全库分别出现 10,169 / 0 / 1,650 次，**没有一次是删除线**。

**实测影响**（同一批 109 题回答，新旧切分器对拍）：

| 项 | 值 |
|----|----|
| 旧切分独有的"变异论断"中被判失败的 | **8 条**（占当期失败论断 52 条的 **15%**） |
| 全部是同一形态 | `6~12→612`、`3~9→39`、`9~30→930`、`3~10→310`、`1~15→115` |
| 修复后新增的正确论断 | 10 条（`常规剂量为每次6~12克` 等，旧切分下**根本不存在**） |

**修法**：只删**成对的**删除线标记，单个 `~` 一律保留——

```python
_MD_INLINE_RE = re.compile(r"~~|[*`_]")   # 原为 r"[*`_~]"
```

⚠️ `split_claims` 只用于判分，**用户看到的回答一直是 `6~12克`**（未被污染）。
即这是一个"只骗指标、不骗用户"的 bug——**比骗用户更难发现**，因为它没有任何用户可见的症状。

### 18b：聚合幻觉率的分母含 `unscored`，与逐题口径不一致

| 位置 | 分母 | 是否正确 |
|------|------|---------|
| `GroundingResult.hallucination_rate`（逐题） | `scored_claims` = `n_claims − unscored` | ✅ |
| `aggregate()`（对外报的数字） | `total` = `n_claims`（**含** unscored） | ❌ |

同一份报告里 `citation_support_rate` 用 818、`hallucination_rate` 用 840，**自相矛盾**。
按 docs 规定的口径（剔除漏判）应为 `52/818 = 6.36%`，而不是报出的 `52/840 = 6.19%`。

**修法**：`aggregate()` 增加 `scored = total − unscored`，四个比率全部改用它；并新增
`"scored_claims"` 字段把分母**如实报出**（分母不透明是这类错误的温床）。

### ⚠️ 连带纠正一个对外报错的数字

之前报的「**真幻觉率 1.10%（9/818）**」**无法从任何一次报告复现**，其算法是：

```
9 = 31(unsupported) − 22(unscored)      ← 把**本就不在分子里**的漏判条数又扣了一次
```

`unscored`（判官漏判、未被判定）本来就**不计入分子**，再扣一次属重复扣减。
正确写法：**已判定论断为分母的直接读数**（本次重跑后填入下表），
不再另造一个"真幻觉率"口径——**口径越多，越容易藏错**。

### 修复后实测（eval_generation_20260923_123357）

| 项 | 结果 |
|----|------|
| 波浪号造成的失败论断 | **0 条** ✓（对拍新旧切分器，全 109 题） |
| 聚合分母修正的影响 | 同一份报告 `72/863 = 8.34%` → `72/820 = 8.78%`——口径改对后**上升**了（诚实的方向） |

### 缺陷 19：又一批系统性语料错字（判官"判错"其实是语料错）

重跑后判官给出的"矛盾"里，多条理由是「资料原文为**胱腹**胁痛/**癥痕**/**底腹**疼痛/**朝血**，
与论断不一致」——**模型写的是对的，语料是错的**（与缺陷 13 完全同型）。
全库核对（判据：正确字应为 0 次）：

| 错字 | 次数 | 应为 | 对照（全库） | 必须词组级的原因 |
|------|------|------|-------------|----------------|
| `胱腹` / `底腹` | 28 / 16 | **脘腹** | `脘` **0** 次 | `胱` 在「膀胱经」合法 53 次 |
| `癥痕` | 20+ | **癥瘕** | `瘕` **0** 次 | `痕` 在「痕迹/瘢痕」合法（356 次） |
| `朝血` / `吐朝` | 6 | **衄血** | `衄` **0** 次 | — |
| `朝蕾定` | 22 | **朝藿定** | — | `朝` 在「朝鲜」等合法（49 次） |
| `底` | 16（`底腹`） | **脘** | 同 `胱腹` | `底` 在「圆底烧瓶」合法 127 次 |

> **这类缺陷是长尾**：13（澹/洶）→ 19（胱/底/痕/朝），每收紧一次判分或修一批错字，
> 幻觉率就动一次。**"再修一个 bug 就能收尾"的预期不成立**——
> 正确做法要么是系统性错字治理（词表 + 扫描器），要么如实公布"语料含已知错字率"。

### 教训（接缺陷 10/14/15）

指标会在两个地方失真，这次是第二个：

1. **坏分母**——框架句、引用行、检索陈述混进论断分母（缺陷 14 已修）；
2. **坏分子**——清洗规则把正确的论断改坏了，判官照实判"矛盾"（本次 18a）。

两者方向相反（一个让数字偏低、一个偏高），且**都不产生任何用户可见症状**。
唯一可靠的探针是：**拿分歧明细逐条看**（8 条全部写着"非612克"这种一眼假的理由）。

## 缺陷 20：判分口径把"非论断"算成幻觉（含 20b 静默归零）

三类被误算进分子的东西（依据来自**逐条分歧明细**，不是推测）：

| 类别 | 实例 | 为什么不该判 |
|------|------|-------------|
| 出处声明 | `根据《中国药典》记载` | 判官不可能在**药典正文**里找到"出处是药典"的依据 |
| 标题式短语 | `黄芪的副作用（不良反应）`、`当归孕妇能用吗` | 模型自己的小节标题，不是论断 |
| 表格行残片 | `大小 直径5〜8mm 同药材` | 表格被切分器拍平后列结构丢失，核验必失败 |

修法：`split_claims_with_stats()` 先按行分流（标题行 / 表格行 / 正文），
**丢弃数如实报出**（`dropped_headings` / `dropped_table_rows`），分母可审计。

⚠️ **代价必须说清**：被判分的只剩**正文论断**——本轮 478 条，另有 **364 行**
标题/表格**未参与判分**。表格内容改由检索层覆盖，判官不判 → 这是**判分覆盖面缺口**，
`幻觉率 9.21%` 只代表正文那部分。同时 `CLAIMS_PER_BATCH` 8→6，漏判从 43 条降到 **1 条**。

### 20b：白名单重建导致新字段"静默归零"

评测器原本按**手工白名单**重建结果对象：

```python
gres.append(GroundingResult(
    n_claims=..., supported=..., unsupported=..., contradicted=...,
    unscored=..., fabricated_quotes=..., judge_error=...))    # ← 少一个字段就永远为 0
```

于是缺陷 20 新加的 `dropped_headings` / `dropped_table_rows` **逐题算对了、聚合恒为 0**。
报告看起来完全正常——**这类"静默归零"比报错危险得多**。

改为 `GroundingResult.from_dict()`（按 `dataclasses.fields` 自省拷贝）后，新增字段自动跟上，
并加回归测试（字典往返 + 聚合）锁住行为。

## 缺陷 22：指标口径缺一环——「Recall@5」此前用 Hit@5 代理

项目书写的是「检索 **Recall@5 ≥ 90%**」，但 README 一直拿 `strict Hit@5` 当代理。
两者**不等价**：`Hit@5` 只要 top-5 命中**至少一个**期望药；而「跨品种比较」「横向条件查询」的期望是
**药集合**（平均 3~5 个药）——只命中其中一个也记 Hit，**偏松**。

**新增为评测器的一等指标**（`src/eval/evaluator.py` 与 `langchain_app/eval.py` 都算，
报告 JSON、`by_type`、CLI 输出都有；+6 项单元测试）：

```
Recall@K = |top-K 命中的期望药| / |期望药|，按题取均值
药名精确匹配（含该药饮片条目），**不判章节**（章节由 strict 口径负责）
full_recall@5 = 期望药**全部**进 top-5 的题占比   ← 最严读法
```

**实测（关重排，109 题）**

| 引擎 | strict@5 | Recall@1 | Recall@3 | **Recall@5** | 全召回@5 |
|------|----------|----------|----------|--------------|---------|
| 手撕版 `src/` | 91.74% | 78.29% | 87.92% | **91.21%** | 89.91% |
| LangChain | 88.99% | 75.54% | 85.40% | **88.46%** | 87.16% |

→ **项目书口径下 src 达标（91.21%）、标准版差 1.54pp**。

**分题型暴露的问题比 Hit 口径更清楚**：`横向条件查询` 的 `Recall@5` 只有 **21%**（strict@5 44%）——
不是"没找到答案"，而是"**凑不齐期望的药**"（该题型期望 3~5 个药，top-5 装不下）。

**重排的第三个侧面**：src 开重排把 `strict@5` 提到 **93.58%**，但 `Recall@5` **降到 89.83%**
（lc 反倒升到 90.29%）——重排会牺牲"把期望药凑齐"的能力，这是默认仍关重排的又一条理由。

## 缺陷 15：判分假阳性——漏判计成幻觉 + 来源截断

### 发现路径

缺陷 14 修完后重跑生成评测，幻觉率不降反升（11.72% → 13.10%）、回答有据率
大跌（78.43% → 66.32%）。这不符合直觉：检索变好了，幻觉怎么会更多？
逐条核查 74 条 unsupported，发现三种成分：

| 成分 | 条数 | 性质 |
|------|------|------|
| ① 判官漏判（reason=「未返回该条判定」） | **25** | 判分基础设施缺陷——批处理输出被 max_tokens 截断，漏的论断里**包含药典逐字原文**（「用于气虚乏力，食少便溏…」） |
| ② 来源截断/判官未见到 | **37** | 判官自己说「含量测定部分被截断」——900 字/来源的上限把色谱条件、限度数值切掉了 |
| ③ 疑似真改写/编造 | **12** | 真幻觉 |

**剔除①②后，真实幻觉率 ≈ 1.75%**——项目书 ≤3% 的目标其实已达标，
之前一直是判分假阳性在虚增。

### 根因（判分器自己的两个缺陷）

1. **漏判被有意计成 unsupported**。`parse_judgement` 的注释写着
   "宁保守，不让幻觉率被低估"——方向听着对，实际是**让判分基础设施的缺陷
   污染被测对象的分数**：漏判的根源是批处理输出被 max_tokens 截断
   （越长的论断越容易被截，而含量测定类长论断恰恰是数值验证的重点对象）。
2. **来源截断 900 字**。`format_sources(max_each=900)`：药典含量测定章节
   动辄上千字（色谱条件/流动相/理论板数/限度），900 字正好把数值切掉，
   判官看不到就判 unsupported。

### 修法

1. 新增 `unscored` 计数：漏判的论断**不计入幻觉分母**
   （`hallucination_rate` 分母改为 `n_claims - unscored`），报告新增
   `unscored_claims` 字段如实报出——漏判比例高说明判分不稳，该重跑的是判分不是被测系统；
2. `format_sources` 的 `max_each` 900 → **1600**（每题 5 来源 × 1600 字，
   判分 prompt 约 8k 字符，仍在预算内）；
3. 引文式第二判官同步：缺条目 → `unscored`（模型明确写 `NONE` 仍是 unsupported，
   那是诚实行为不是漏判）。

> ⚠️ 这次修正**方向上是放宽**，必须有边界：`unscored` 单独计数并进报告，
> 排除比例若失控（比如 >20%），说明判分不可信，应当重跑而不是欣然接受低幻觉率。
> "放宽"与"放水"的差别就在这个字段是否被如实监督。

## 教训

1. **"诚实拒答"可能是检索缺陷的遮羞布**——模型说"资料未收录"是诚实行为，
   但如果资料本该有，那就是检索缺陷借了生成的脸。判断"拒答是否合理"必须回到语料验证。
2. **"宁保守"的判分方向会自我污染**：判分基础设施的任何缺陷（截断、漏判）
   都单方向地推高被测对象的"幻觉率"——一个只会往坏里错的度量，
   长期看比没有度量更危险，因为它让所有改进都显得无效。
